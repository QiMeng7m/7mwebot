> 实现入口：`src/points/expansion.py`；群指令见 README「扩展玩法」。
> 下文保留原始规划，作为后续调参与迭代参考。

> 第一阶段已完成：境界上限 20 境、装备品阶

## P0：优先落地（建议下一迭代）

### 1. 装备套装与套装效果

- **设计**：给装备目录增加 `set_id`，同套装备穿戴 2/4 件触发不同档位效果。
- **示例套装**：诛仙套（攻击 +10% / 4 件：主动技能伤害 +20%）、鸿蒙套
  （攻防 +12% / Boss 伤害 +15%）、造化套（全属性 +15% / 技能冷却 -20%）。
- **数据**：`equipment.json` 增加 `set_id`；`skills.py` 或新 `sets.py` 定义套装
  效果；`PowerBreakdown` 增加 `set_attack/set_defense` 或并入技能效果。
- **展示**：`商店`、`我的装备`、`武力值` 显示套装进度与激活状态。
- **理由**：与刚上线的品阶/技能天然衔接，能显著提升高阶装备的收集动力。

### 2. 技能升级 / 技能书

- **设计**：主动/被动技能增加等级 1~5，消耗「技能书」或灵石升级；效果按
  等级放大，冷却小幅缩短。
- **来源**：Boss 掉落、抽奖奖池、每日任务、钓鱼稀有奖励。
- **数据**：新增 `skill_levels(chat_id, sender_id, skill_id, level)` 或在
  `equipment_owned` 旁记录；`skills.py` 增加等级倍率。
- **理由**：让已获得的技能持续可投入，避免“拿到即毕业”。

### 3. 每日 / 周常任务

- **设计**：每天 3~5 个轻量任务（发言、签到、打坐、切磋、钓鱼、Boss），
  完成给灵石/修炼值/技能书；周常给稀有奖励。
- **数据**：新增 `daily_tasks(chat_id, sender_id, day, task_id, progress,
  claimed)`；任务定义放 `src/points/tasks.py`。
- **指令**：`任务`、`领取任务奖励`；后台可查看完成率。
- **理由**：把现有分散玩法串成日常循环，提升留存，且实现成本可控。

## P1：第二阶段

### 4. 秘境爬塔（PvE）

- 每层一个守关怪物，按攻击/防御结算；通关给灵石、装备材料、技能书。
- 层数永久记录，可重复挑战已通关层；每周重置部分奖励。
- 复用 `roll_damage` / `PowerBreakdown`，新增 `src/points/dungeon.py` 与
  `dungeon_progress` 表。
- 可作为装备品阶材料的主要产出。

### 5. 装备词条洗练

- 高阶装备随机 1~3 条词条（攻击%、防御%、暴击、Boss 伤害、切磋胜率），
  花灵石洗练并选择保留。
- 新增 `equipment_affixes` 表；`PowerBreakdown` 汇总词条。
- 与套装/技能共同构成装备 build 深度。

### 6. 擂台赛 / 赛季段位奖励

- 每月/每赛季按切磋段位发放称号、灵石、限定装备。
- 可加「周擂台」：报名后系统随机配对，结算积分。
- 复用 `duels`、`duel_rank`、赛季表。

## P2：中长期

### 7. 师门 / 结义 / 组队

- 成员创建或加入师门，师门有等级、贡献、师门技能；组队挑战副本/Boss 有加成。
- 新增 `guilds` / `guild_members` 表；需要权限与解散/转让流程。

### 8. 交易行 / 拍卖行

- 玩家挂售装备、鱼饵、技能书，收取手续费；一口价 + 限时拍卖。
- 需要处理并发扣款、重复上架、过期返还、防刷与经济通胀。
- 建议在套装/词条稳定后再做。

### 9. 宠物 / 灵兽

- 宠物提供被动属性或主动技能，可培养/进化；与坐骑槽位区分。
- 可复用技能系统，新增 `pets` 表。

### 10. 炼丹 / 生活技能

- 采集 + 炼丹产出临时增益丹（攻击、防御、Boss 伤害、钓鱼稀有）。
- 与钓鱼/打坐/功法形成生活玩法闭环。

### 11. 天气 / 时辰 / 世界事件

- 不同天气影响钓鱼稀有度、Boss 属性；整点世界事件给全群 buff。
- 实现成本低、氛围强，可作为活动型功能。

## P3：锦上添花

### 12. 转世 / 轮回

- 满级/满境后可转世，重置等级与境界，换取永久转世点数和专属称号。
- 适合作为超长期目标，需谨慎设计避免挫败感。

### 13. 跨群榜单 / 群战

- 多群联合排行榜、群间对战周。
- 依赖多群数据聚合与赛季结算，建议最后做。

## 建议发布顺序

1. **套装 + 技能升级 + 每日任务**（一个版本，形成“收集→养成→日常”闭环）
2. **秘境爬塔 + 词条洗练**（提供稳定的材料与 build 深度）
3. **擂台赛 + 赛季奖励**（强化 PvP 目标）
4. **师门/组队 → 交易行 → 宠物/炼丹 → 天气事件**
5. **转世 → 跨群玩法**

## 风险与约束

- **经济通胀**：所有新产出（技能书、材料、灵石）需要配套回收口（洗练、升级、
  手续费、拍卖税）。
- **并发与幂等**：交易行、组队、副本结算必须沿用现有
  `UNIQUE(message_id, reason)` / 条件 INSERT 模式。
- **配置化**：新玩法优先做成 `data/*.json` 目录 + 校验，方便后台调整。
- **兼容旧数据**：新增表使用 `CREATE TABLE IF NOT EXISTS`，新增列走
  `_ensure_columns` 迁移。
